# PsycedelicAI Project Map

> A practical map of the public PsycedelicAI GitHub organisation.

This document explains the main repositories, documentation areas and project
relationships within the public PsycedelicAI ecosystem.

It is intended to help new readers understand where to begin, what each project
contains and how the different parts may relate.

The repositories should not automatically be treated as one single implemented
system.

Some projects are methodological.

Some are conceptual.

Some are experimental.

Some are archival.

Some are documentation and orientation layers.

The relationships described here are based on publicly documented concepts,
recurring terminology, project history and links between repositories.

- terminology
- relationships between documents
- current project state
- unfinished work
- provenance
- uncertainty

### Important concepts

- AI Continuity
- Portable Workstate
- Memory Bank
- Freeze State
- Context Reconstruction
- Context Compiler
- project state
- human authority
- continuity testing

### Core distinction

```text
AI memory
```

- a public methodology

- a basis for future experiments

### Recommended use

# 4. Security and Trust Architecture

## `high-security-facility-concept`

[Open repository](https://github.com/psycedelicAI/high-security-facility-concept)

### Role

A conceptual trust and security architecture for high-security environments.

### Main purpose

The project explores how a complex security environment can be understood as
a connected system rather than as a collection of isolated controls.

### Areas of exploration

- identity
- trust zones
- credentials
- access control
- device context
- physical possession
- authorisation
- revocation
- surveillance
- governance
- monitoring
- recovery
- auditability
- operational coordination
- human oversight

### General architectural principle

Security is not only a matter of adding more controls.

It also depends on:

- who is requesting access
- what they are allowed to do
- where the request originates
- which context applies
- what has changed
- who approved the action
- how the action can be reviewed
- what happens if the system fails

### Status

This repository should be understood as a conceptual and architectural body of
work unless a specific component is explicitly documented as implemented.

It is not automatically a complete production facility design.

### Recommended use

Start here if you are interested in:

- trust architecture
- security zones
- human authority
- access and identity
- operational security
- system failure and recovery
- security as a connected architecture

# 5. Human-AI Collaboration

## `Symbiosis`

[Open repository](https://github.com/psycedelicAI/Symbiosis)

### Role

A public exploration of human-AI collaboration and the relationship between
human direction and AI-supported work.

### Main purpose

Symbiosis examines how human experience and AI capabilities can work together
without confusing their different roles.

### Psycedelic contributes

- lived experience
- purpose
- intuition
- values
- creativity
- emotion
- judgment
- responsibility
- personal meaning

### AI contributes

- analysis
- research
- structure
- memory support
- pattern recognition
- documentation
- comparison
- synthesis
- connections across time

### Important boundary

AI can support human work.

AI can analyse, structure, compare and propose.

Human beings remain responsible for:

- values
- purpose
- meaning
- approval
- important decisions
- external commitments
- responsibility for published work

### Status

Symbiosis includes conceptual and experimental material.

It should not automatically be interpreted as a single finished software product.

### Recommended use

Start here if you are interested in:

- human-AI collaboration
- AI-assisted creativity
- shared working methods
- human authority
- responsible use of AI
- the relationship between tools and human judgment

# How to Interpret the Public Work

The public repositories contain different kinds of material.

When exploring them, distinguish between:

## Directly documented facts

Information explicitly stated in a README, document, file or project history.

## Concepts

Ideas, models, principles or architectures that describe a possible approach.

## Experiments

Tests, demonstrations or working examples intended to explore an idea.

## Prototypes

Early technical or methodological implementations that may not yet be complete.

## Proposals

Ideas for future development that are not necessarily implemented.

## Historical material

Older work preserved because it shows how the ideas developed.

## Private or unavailable material

Work that may exist outside the public repositories or may not be available to
the reader.

A connection between projects should be treated as stronger when it is supported
by:

- explicit links
- repeated terminology
- shared documentation
- development history
- clearly stated relationships

A connection should be treated as weaker when it is based only on:

- similar themes
- similar names
- external interpretation
- assumptions about the author's intentions

# Current Public Ecosystem Summary

The public PsycedelicAI GitHub organisation can be understood as a growing
collection of:

- human-AI collaboration concepts
- AI continuity methods
- knowledge and documentation structures
- trust and security architecture
- experimental workflows
- public communication
- historical and archival material

The central question connecting much of the work is:

> How can human intention, context, meaning, responsibility and useful work
> continue across changing systems without losing human authority?

The projects approach this question from different directions.

Some focus on collaboration.

Some focus on continuity.

Some focus on trust and security.

Some focus on documentation.

Some preserve the development history behind the ideas.

Together, they form a public map of an ongoing body of work.
