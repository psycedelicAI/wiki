# PsycedelicAI Wiki

Welcome to the official **PsycedelicAI Wiki**.

This wiki documents the identity, projects, methods, experiments, and technical ideas developed under the name **PsycedelicAI**.

PsycedelicAI is not only an AI project. It is a working relationship between human direction and AI-supported memory, analysis, documentation, and continuity.

> **Psycedelic sees the direction. AI helps preserve the map.**

---

## About PsycedelicAI

**PsycedelicAI** is the shared project identity of:

- **Psycedelic** — human direction, experience, intuition, ideas, and final decisions
- **AI** — analysis, structure, memory support, documentation, and continuity

The human side remains responsible for meaning, values, priorities, publishing, and project direction.

AI is used as a development partner to help:

- capture fragmented ideas
- identify connections
- structure complex material
- preserve project context
- create technical documentation
- compare models and approaches
- maintain continuity between sessions
- turn evolving concepts into reviewable documents

PsycedelicAI is built around the principle that creative and technical work can become stronger when human intuition and machine-assisted structure are used together.

## Main Projects

### High-Security Facility Concept

[High-Security Facility Concept](https://github.com/psycedelicAI/high-security-facility-concept) is a conceptual trust-architecture framework for high-security physical and operational environments.

The project explores how security can be designed as a connected system rather than as a collection of isolated controls.

Its areas of interest include:

- identity
- trust boundaries
- zones
- credentials
- movement
- devices
- surveillance
- governance
- incident handling
- resilience
- recovery
- controlled degradation
- human and operational factors

The project is conceptual and documented. It is not presented as a certified security standard, finished engineering product, or replacement for professional security assessment.

## Working Principles

PsycedelicAI development is guided by several recurring principles:

### Human Authority

The human creator remains responsible for direction, meaning, values, and final decisions.

### Structured Continuity

Important context should be stored in structured, versioned, and reviewable documents.

### Modular Documentation

Projects should be divided into focused documents instead of relying only on one large and difficult-to-maintain file.

### Explicit Relationships

Documents should explain how they relate to other documents, projects, experiments, and historical versions.

### Clear Status

Established information, proposed ideas, experiments, assumptions, and unresolved questions should be distinguished from one another.

### Review Before Canonical Use

AI-generated material is treated as a draft or development contribution until it has been reviewed and accepted by the human project owner.

### Practical Systems Thinking

Technical systems are considered together with people, processes, permissions, physical environments, failure modes, and recovery.

## Contributions

Contributions, corrections, suggestions, and improvements are welcome.

Before contributing, please consider:

1. Keep documentation clear and structured.
2. Distinguish facts, proposals, assumptions, and experiments.
3. Preserve the relationship between documents.
4. Avoid removing historical context without documenting the change.
5. Use descriptive commit messages.
6. Keep project terminology consistent.
7. Treat security-related material responsibly.
8. Do not present conceptual material as validated production technology.

To contribute:

1. Fork the repository.
2. Create a branch for your changes.
3. Add or improve documentation.
4. Review the changes carefully.
5. Submit a pull request.
