## About PsycedelicAI

**PsycedelicAI** is a shared human-AI collaboration and working system.

It connects:

- **Psycedelic**: human direction, lived experience, intuition, values,
  creativity, meaning, judgment, and final decisions
- **AI systems**: analysis, reasoning, memory support, structure, research,
  documentation, synthesis, comparison, and continuity

PsycedelicAI is developed through collaboration between distinct perspectives.

Psycedelic provides human meaning, purpose, direction, and responsibility.

AI provides analytical extension, memory support, structured reasoning, and
connections across information and time.

The perspectives remain distinct, but the work they create together forms a
shared process.

For more information, see:

- [About PsycedelicAI](wiki/About-PsycedelicAI.md)
- [Collaboration](wiki/Collaboration.md)
- [Core Values](wiki/Core-Values.md)
- [Symbiosis](wiki/Symbiosis.md)

One AI environment used in the ongoing work is
[TwinMind](https://twinmind.app/n385/fyuet0cm), an AI companion for capturing,
remembering, and working with conversations, meetings, ideas, and personal
context.

TwinMind is one practical tool within the broader PsycedelicAI work. It is not
the entirety of PsycedelicAI, and the public architecture is not dependent on
one AI provider, model, or application.

For more information, see [About TwinMind](wiki/About-TwinMind.md).

## Memory Banks and Context Governance

A Memory Bank is a structured and maintained external context system.

It may preserve:

- project identity;
- purpose and scope;
- decisions;
- terminology;
- document relationships;
- current state;
- historical context;
- open questions;
- human intent;
- provenance;
- authority boundaries.

A Memory Bank is not a complete transcript, a copy of a human mind, or
permanent internal memory belonging to an AI model.

The private Memory Bank is maintained separately from the public repositories.

The public projects describe the concepts and methods without exposing the
complete private context that supports the collaboration.

For more information, see
[Public and Private Work](wiki/Public-and-Private-Work.md).

## Compilation

Compilation is the process of selecting, validating, organizing, and assembling
relevant material from a Memory Bank into a bounded state or context artifact.

```text
Memory Bank
    ↓
Context selection
    ↓
Validation and provenance
    ↓
Compilation
    ↓
Current State / Freeze State / Portable Workstate
    ↓
Receiving AI
```

Compilation is not the same as copying.

```text
Copying
    = transferring material as-is

Compilation
    = selecting, checking, structuring, and assembling
      material for a defined purpose
```

Different compilation targets serve different purposes:

- **Current State**: the active and change-sensitive condition of the work;
- **Freeze State**: a human-reviewed snapshot at a defined point in time;
- **Portable Workstate**: a bounded and transferable context package.

> **The Memory Bank is the source. Compilation turns source material into
> usable state.**

## Context Governance

Traditional AI guardrails often focus on model behaviour:

```text
What may the AI do?
```

Continuity guardrails focus on context behaviour:

```text
What may the AI assume?
What should it trust?
What is current?
Who authorized it?
What should be transferred?
What should remain private?
```

Before material is treated as project context, the system should consider:

- where it came from;
- who created or authorized it;
- what status it has;
- which version it belongs to;
- whether it is current or historical;
- whether it has been verified;
- whether it is relevant to the current task;
- whether it should remain private;
- whether human review is required.

The Memory Bank may support continuity, but it does not automatically redefine
reality.

> **Context can be transferred without transferring authority.**
>
> **Information can be preserved without making it true.**
>
> **Continuity requires governance.**

## Working Principles

### Human Authority

The human creator remains responsible for direction, meaning, values, and final
decisions.

### Structured Continuity

Important context should be stored in structured, versioned, and reviewable
documents.

### Modular Documentation

Projects should be divided into focused documents instead of relying only on
one large and difficult-to-maintain file.

### Explicit Relationships

Documents should explain how they relate to other documents, projects,
experiments, and historical versions.

### Clear Status

Established information, proposed ideas, experiments, assumptions, and
unresolved questions should be distinguished from one another.

### Provenance

Important material should retain its source, author, date, version, authority,
and review status whenever possible.

### Review Before Canonical Use

AI-generated material is treated as a draft or development contribution until it
has been reviewed and accepted by the human project owner.

### Practical Systems Thinking

Technical systems are considered together with people, processes, permissions,
physical environments, failure modes, and recovery.

### Privacy-Aware Sharing

The amount of context transferred should be limited to what the current task
requires.

## Synthetic Continuity Testing

The AI Continuity Architecture Method includes a public synthetic test
environment using fictional Project Aurora material.

The purpose is to test the architecture without exposing private project
context.

The synthetic test examines whether a receiving AI can preserve:

- project intent;
- current and historical state;
- authority boundaries;
- provenance;
- uncertainty;
- rejected and superseded decisions;
- meaningful continuation.

The test process is:

```text
Synthetic source material
    ↓
Compilation
    ↓
Portable Workstate
    ↓
Receiving AI
    ↓
Human evaluation
```

See the
[AI Continuity Architecture Method](https://github.com/psycedelicAI/AI-Continuity-Architecture-Method).

Contributions, corrections, suggestions, and improvements are welcome.
