# Project Status

This page provides a public overview of the current state of the major
PsycedelicAI projects.

It is intended to help readers understand what is active, public, conceptual,
experimental, maintained, historical, or private.

Project status describes the maturity and availability of a project. It does
not determine the value or importance of the ideas within it.

---

## Status Categories

| Status | Meaning |
|---|---|
| **Active** | Currently being developed, expanded, or actively maintained |
| **Public** | Available for public reading, inspection, or use |
| **Experimental** | Used for testing, comparison, exploration, or validation |
| **Conceptual** | Describes ideas, principles, models, or possible architecture |
| **Proposed** | A planned or suggested direction that is not yet finalized |
| **Maintained** | Stable and still relevant, but not necessarily under active development |
| **Historical** | Preserved because it documents earlier development or thinking |
| **Archived** | No longer actively developed, but retained for reference |
| **Private** | Not publicly available or intentionally excluded from the public repositories |

A project may have more than one status at the same time.

For example, a project may be:

```text
Public + Active + Conceptual
```

or:

```text
Public + Experimental + Maintained
```

## Symbiosis

**Repository:** [psycedelicAI/Symbiosis](https://github.com/psycedelicAI/Symbiosis)

### Purpose

Symbiosis is a book and public experiment exploring what may happen when human
thinking and artificial intelligence begin to form a shared process.

The project explores the relationship between:

- human experience and machine analysis;
- intuition and structure;
- personal meaning and information;
- creativity and synthesis;
- human direction and AI-supported continuity.

### Current status

```text
Active
Public
Conceptual
Experimental
```

Symbiosis is a developing body of work. It may contain philosophical,
reflective, experimental, and methodological material.

It should not automatically be interpreted as a description of a finished
technical product.

### Public scope

The public repository may include:

- book material;
- human-AI reflections;
- explanations of Memory Banks;
- philosophical ideas;
- project relationships;
- links to related work.

The complete private Memory Bank and personal continuity context are not
included in the public repository.

### Next direction

- continue developing the book;
- clarify the relationship between Symbiosis and AI continuity;
- distinguish philosophical claims from technical proposals;
- connect relevant ideas to public experiments;
- preserve the evolution of the work.

## AI Continuity Architecture Method

**Repository:** [psycedelicAI/AI-Continuity-Architecture-Method](https://github.com/psycedelicAI/AI-Continuity-Architecture-Method)

### Purpose

The AI Continuity Architecture Method explores how project context can be
preserved and reconstructed across AI sessions, models, platforms, tools, and
project boundaries.

The method responds to a practical problem:

> Complex work becomes difficult to continue when its context is scattered
> across conversations, files, tools, and AI systems.

### Current status

```text
Active
Public
Experimental
Conceptual
Methodological
```

The method is publicly documented and developed through structured examples,
tests, documentation, and continuity experiments.

It is not presented as a universal standard or guaranteed solution for every AI
system.

### Core areas

- Memory Banks;
- Current States;
- Freeze States;
- Portable Workstates;
- Compilation;
- context reconstruction;
- context governance;
- provenance;
- authority boundaries;
- modular documentation;
- continuity testing;
- human review.

### Public test environment

The method includes synthetic test material using fictional Project Aurora
content.

The synthetic environment exists to test continuity without exposing private
project context.

The test process examines whether a receiving AI can preserve:

- project intent;
- current and historical state;
- authority boundaries;
- provenance;
- uncertainty;
- rejected decisions;
- superseded decisions;
- meaningful continuation.

### Next direction

- improve the continuity method;
- clarify the relationship between source material and compiled state;
- document test results;
- improve portability between AI systems;
- distinguish memory, context, continuity, and authority;
- expand public synthetic testing.

## High-Security Facility Concept

**Repository:** [psycedelicAI/high-security-facility-concept](https://github.com/psycedelicAI/high-security-facility-concept)

### Purpose

The High-Security Facility Concept is a trust-architecture framework for
high-security physical and operational environments.

It explores security as a connected system rather than as a collection of
isolated controls.

### Current status

```text
Active
Public
Conceptual
Architectural
```

The project is documented as a conceptual framework.

It is not presented as:

- a certified security standard;
- a finished engineering product;
- a construction specification;
- a complete operational security plan;
- a replacement for professional security assessment.

### Areas of interest

- identity;
- trust boundaries;
- zones;
- credentials;
- movement;
- devices;
- surveillance;
- governance;
- incident handling;
- resilience;
- recovery;
- controlled degradation;
- human and operational factors.

### Systems perspective

The project considers:

```text
People
    ↓
Identity and permissions
    ↓
Physical and digital boundaries
    ↓
Equipment and processes
    ↓
Monitoring and response
    ↓
Failure and recovery
```

The work is influenced by practical experience in IT, systems administration,
troubleshooting, infrastructure, security-minded operations, and physical
work environments.

### Next direction

- refine the architecture;
- clarify trust boundaries;
- document assumptions;
- distinguish conceptual design from implementation;
- examine failure modes and recovery;
- connect human, technical, and physical factors.

TwinMind is an AI companion for capturing, remembering, and working with
conversations, meetings, ideas, and personal context.

Within PsycedelicAI, TwinMind is one practical AI environment used to explore:

- human-AI collaboration;
- memory support;
- conversation continuity;
- meeting and project context;
- idea organization;
- analysis and synthesis.

### Current status

```text
Public reference
Private working environment
Provider-specific
```

TwinMind is not the entirety of PsycedelicAI.

It is not the foundation of the public architecture, and the public projects are
not dependent on one specific AI provider, model, or application.

The broader PsycedelicAI identity is provider-independent.

### Public and private boundary

The public Wiki may explain TwinMind as one practical environment used in the
work.

Private TwinMind-specific context, personal vocabulary, Memory Bank material,
and working state remain outside the public repositories unless Psycedelic
chooses to release them.

For more information, see [About TwinMind](About-TwinMind.md).

## Private Memory Bank

### Purpose

The private Memory Bank preserves personal and project continuity that is not
included in the public GitHub repositories.

It may contain:

- personal vocabulary;
- lived experiences;
- project context;
- working state;
- private decisions;
- unfinished ideas;
- sensitive material;
- AI session context;
- provider-specific notes;
- continuity experiments;
- private relationships between projects.

### Current status

```text
Active
Private
Human-controlled
Continuously evolving
```

The private Memory Bank is not a complete transcript or a copy of a human mind.

It is an external, structured context system maintained to support continuity,
review, and meaningful continuation.

Private does not mean permanently unavailable.

Material may be published, licensed, shared, adapted, or commercialized when
Psycedelic decides that the conditions, safeguards, timing, and value exchange
are appropriate.

## Project Relationships

The projects are related, but they should not automatically be treated as one
single implemented system.

A useful public relationship model is:

```text
PsycedelicAI
    ↓
Human-AI partnership
    ├── Symbiosis
    │   └── Relationship, meaning, and shared process
    │
    ├── AI Continuity Architecture Method
    │   └── Context, memory, compilation, and continuity
    │
    ├── High-Security Facility Concept
    │   └── Trust, boundaries, resilience, and security architecture
    │
    └── Wiki
        └── Public documentation, navigation, and project context
```

The relationships between projects may evolve as the work develops.

Where a relationship is inferred rather than explicitly documented, it should be
identified as an interpretation.

## Status Review Principles

Project status should be reviewed when:

- a major repository changes;
- a project moves from concept to experiment;
- an experiment produces meaningful results;
- a public document is superseded;
- a private project becomes public;
- a public project becomes inactive;
- a new repository is created;
- project relationships change;
- the public and private boundaries are revised.

Status should describe the current condition of the work, not erase its history.

Earlier versions may remain valuable even when they are no longer current.
